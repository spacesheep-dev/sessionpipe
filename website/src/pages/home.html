An open protocol, and a client, for what your coding agents are doing.

One install hooks Claude Code, Codex, Gemini CLI, Antigravity and Devin. Every event is filtered to the privacy tier you choose, secrets are removed on your machine, and it goes to your server, to a file, or nowhere at all.

§01

How it works

hooks → protocol → receivers
  1. hook

    A command the agent already runs

    At the moments it knows about: a session started, a tool is about to run, it is waiting for you. sessionpipe's hook hands the payload to a background worker and exits in under 150 ms.

  2. protocol

    One envelope for every agent

    session.started, tool.ended, attention.needed: 17 types in protocol 1. Facts and timestamps, never a verdict: "stuck" and "done" are for the receiver to decide.

  3. receivers

    Sent where you say, and kept until it lands

    A sink is a file, stdout or a URL. The outbox on your disk moves a sink's cursor only after a 2xx and keeps 30 days, so a laptop offline for a week loses nothing.

§03

One event, start to finish

a permission request, recorded

Claude Code asks permission to run a command. Here is what it hands the hook, what the adapter makes of it, and what a destination set to tier 0 actually receives.

  1. inWhat Claude Code fires

    {
  "hook_event_name": "PermissionRequest",
  "session_id": "ed6c7665-589f-…",
  "cwd": "~/…/ws2",
  "transcript_path": "~/.claude/projects/…",
  "permission_mode": "default",
  "tool_name": "Bash",
  "tool_input": {
    "command": "cat /nonexistent-file-xyz",
    "description": "Try to read a file…"
  }
}

    Its own field names, its own format. Codex and Gemini CLI say the same thing differently.

  2. adaptWhat the adapter makes

    {
  "protocol": 1,
  "type": "attention.needed",
  "time": "2026-09-28T03:44:50.515Z",
  "tier": 1,
  "harness": { "name": "claude-code" },
  "session": { "id": "ed6c7665-…" },
  "privacy": { "rulesets": ["secrets@1"] },
  "data": {
    "attention_id": "perm-1bb18c870624a063",
    "kind": "permission",
    "tool": "Bash",
    "message": "Bash cat /nonexistent-fi…"
  }
}

    The same envelope for every agent. Secrets in message would already be gone.

  3. outWhat a tier-0 sink receives

    {
  "protocol": 1,
  "type": "attention.needed",
  "tier": 0,
  "…"
  "data": {
    "attention_id": "perm-1bb18c870624a063",
    "kind": "permission"
    "tool": "Bash",
    "message": "Bash cat /nonexistent-…"
  }
}

    "Needs you", without the words. The filter is an allowlist per event type, so a field nobody listed never leaves.

§04

You choose how much leaves

four tiers, per destination

Each destination is set to a tier, and each receiver states the most it will accept. The lower of the two wins. Every tier includes the one above it in this list.

  1. 0

    presence

    Session id, state, timing, machine, folder, repo, branch, model, title; the kind of attention needed.

    A board of who is working, who needs you, who is done.

  2. 1

    actions

    + tool names, durations, ok or error, file paths, the attention message, subagents.

    An activity feed.

  3. 2

    conversation

    + your prompts and the assistant's replies, redacted.

    Memory, search, recaps.

  4. 3

    full

    + tool input and output, thinking, raw hook lines.

    Full replay, on a server you own.

The secrets ruleset runs on every string above tier 0 and cannot be turned off. PII reduction is a second pass you can turn on. sessionpipe tail --tier N shows exactly what a tier sends before you point it anywhere. The privacy spec.

§07

The protocol

CC BY 4.0 · Draft

The protocol is the contract. The client is one way to speak it; anyone can write the other end.

ProtocolThe envelope, the event vocabulary, the session block, the tiers. HTTPDiscovery, batches, errors, retry, idempotency. PrivacyThe four tiers in detail, the secrets and PII rulesets. ControlPermission answers, prompts at the next turn, cancel, acks. AdaptersThe harness registry and each one's mapping. VersioningThe protocol integer, capabilities, deprecation. SchemasJSON Schemas for every message, generated from code. ConformanceReal payloads, vectors and scenarios, in the repository.
  • 100 %line and branch coverage of every source file, enforced
  • 89shared control vectors every verifier must agree on
  • 66redaction vectors, each idempotent
  • 19delivery scenarios a receiver is scored on

Every registered harness has fixtures recorded from real payloads, and a mutation suite feeds each one 40 to 60 broken shapes to prove no adapter can throw. Point the suite at your receiver to score it; the spec stays Draft until two independent receivers pass.

$npx sessionpipe-conformance https://your-receiver.example

§08

Get started

a minute per machine

  1. Connect a machine to a receiver

    It shows six digits; approve them on any device where you're signed in to the receiver. That one approval is the whole setup.

    $npx sessionpipe connect your-receiver.example

  2. Or only the hooks

    Detects the harnesses here, writes their hooks and backfills 30 days into a local outbox. Nothing leaves the machine yet.

    $npx sessionpipe install

  3. Watch, with no server

    One event per line from the local outbox: exactly what a tier-1 sink would receive.

    $sessionpipe tail --tier 1

  4. Add a sink

    Reads the receiver's /.well-known/sessionpipe, caps the tier at its max_tier and sends one heartbeat as a test.

    $sessionpipe sink add https://your-receiver.example --tier 1 --token <t>

The full guide: the Claude desktop app, the reference receiver in Docker, spacesheep, a Slack webhook, uninstalling. Every command is in the docs.

§09

Privacy and security

three promises

  1. No telemetry.

    sessionpipe reports to the destinations you configured and to nobody else. This site has no analytics, no cookies, and loads nothing from anyone.

  2. Secrets never leave.

    Redaction runs on your machine before anything is written to the outbox, so a receiver never sees what was removed.

  3. Your server, or none.

    A file, stdout, the reference receiver on your laptop, or any HTTPS endpoint that speaks the protocol. There is no sessionpipe cloud.

Control: a receiver carries commands, it can never forge one

Every command is signed on your device with a passkey, and the machine checks the exact bytes against keys enrolled at its own terminal, the nonce, the age, the folder allowlist, and that a permission you answer is still open. Nothing is ever auto-allowed. The control spec · Security and the threat model.

sessionpipe control pair https://your-receiver.example
sessionpipe control folders add ~/work
sessionpipe control mode safe   # or auto

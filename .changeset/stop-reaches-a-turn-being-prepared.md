A Stop now reaches a turn the daemon is still preparing. A cancel only found a turn once its child process had been asked for, which is after the login check (`claude auth status`, seconds when it is not cached) and, for a message with files, after their download: a Stop in that window was acked "nothing is running in that session…" and the turn then started; for a new session the Stop waited for the start to finish and ended `refused` `no_session`. The turn is in hand from the moment its message's turn comes: the Stop is acked `taken` and `delivered` ("stopped the turn this computer was running for that session"), the turn never starts, a message's own ack is `delivered` with "(The turn was cancelled.)", and a start that never began is acked `failed` with code `cancelled` and "stopped before it started, as asked: no session was created". A Stop for a session whose start is running stops that start, not the message waiting behind it, and no longer waits for a start to end.

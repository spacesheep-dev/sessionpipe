A control `start` can say how much the new session may do and which model it runs (CONTROL.md §2, §3.1, §5 step 8, §6 Options; ADAPTERS.md "Start options"). `permission` is one of four levels, `read`, `safe`, `edits` and `auto`, with nothing above `auto`; `model` is the harness's own id, passed as one argument. The machine's `mode` is the ceiling, and a start above it, or at a level the harness has no flag for, is refused `permission` before anything is taken or run (the daemon's old `mode` code). On a machine in `inherit` mode a start that names no level runs with no permission flag, as the person's own sessions there do, and one that names a level may name only `read` or `safe`, since sessionpipe can't rank the person's own default; `inherit` is never a level a command names. The hello advertises what each harness takes here (`start`, capped by the mode: Claude Code's levels from its `--help`, Codex's models from its own cache; a harness's default may be `inherit`). A start's `cwd` may be `~` or `~/…`, read under the daemon user's home, so a receiver can start a session in a folder an event reported without the machine ever telling it its home. A start's level and model are recorded with the session, and every later resume or fork runs at the narrower of that and the machine's mode then (at most `safe` on an inherit machine for a session that named a level). The `taken` and `delivered` acks of a start carry `applied` (its `permission` may be `inherit`); a model the harness rejects ends `failed` with code `model`. An ACP agent takes neither option: a start that names one is refused, never run without it. Each command kind now has a closed set of fields, so a field a machine doesn't know is refused rather than ignored. `sessionpipe control status` shows the options per harness. A start whose text begins with a dash no longer reaches `claude -p` as a flag.

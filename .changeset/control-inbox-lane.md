Control: an `inbox` delivery mode (CONTROL.md §6.3). A message for a session somebody has open is written into Claude Code's own local inbox for it, so the turn runs in that live process, in the mode the person left it in, in the window or thread they are already looking at — instead of being answered by a copy. It sits between `turn` and `api` on the ladder, is chosen before the first byte (one live registry record in the account the session resolved to, the inbox protocol, an interactive process, a socket of this uid, a matching process start time read in UTC, an idle session, a signed `iat` at most 120 s old, a permission class), and is never retried or re-sent on another mode once a byte is written. The envelope declares THE MACHINE's own permission class, `bypass` only on an `inherit` machine whose account defaults to bypass and may; the mode is used only where that equals the session's own class. A write is confirmed by the row the session writes for the turn it caused, carrying that message's own mark; unconfirmed it acks `failed` with code `held`, says nothing was duplicated, and keeps the mode shut for that session while the message could still be released to it. The writer is the daemon's alone: not exported from `sessionpipe-core`, no CLI verb.

Core: `liveRecords`/`liveRecord` read every live session registry row (`liveProcess` is now a question about that list); `findTranscripts` and `resolveHome` pick which Claude Code account a session id belongs to when several hold its transcript, and a message for an id that is filed in two accounts with none of them holding it open is refused `ambiguous_home`. New `hookMode`, `peerClass`, `modeRank`, `CLAUDE_MODES`, `homeSettings`, `NO_HOME_SETTINGS`, `relaunchMode`, `peerAsk`.

Each session's own permission mode is recorded from its hooks (`permission_mode` on every Claude Code payload), in the daemon's own state and no Claude Code home, latest word wins, nothing written when it hasn't changed. A relaunch (`resume`, `fork`) of a session the daemon did not start now re-asserts just the narrowing the session itself chose — `plan` and `dontAsk` always, `acceptEdits` where the account's own default is at least that wide, nothing otherwise, and never `auto` or `bypassPermissions`; a start's own recorded options (#138) are untouched. The ack's `detail` says the mode the new turn recorded, and on an `auto` machine whose Claude Code has auto disabled, that the turn ran in Manual mode.

A copy says so: `CLAUDE_CODE_RESUME_SOURCE_ALIVE` on a fork whose source is still open, a note in the message telling the copy it is one, `copy_of` on the ack, a record with a date and a reason (written beside the plain id map an older daemon reads), a `limits.copies_per_day` cap refused as `copy_limit`, and no copy of a copy. A peer-delivered ask is read as the turn's ask and marked `injected` on `turn.transcript`. `daemon.log` is created 0600, like the files beside it.

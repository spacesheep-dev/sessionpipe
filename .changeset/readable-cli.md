cli: output a person can read at a glance, and one place that says whether this computer is fine

`sessionpipe doctor` now starts with a verdict (`All good`, or how many things need attention), sets out what it looked at in groups of aligned rows, each with a mark and a word, and ends with **To fix**: one plain sentence and, where there is something to run, one command each, in the order to run them. `sessionpipe status` is the same in a few lines. `--json` keeps its shape on both.

Trouble that only the daemon's log knew is on that page: a disk that filled up, a key the service can't read from the keychain, a pool with no account left to try, a receiver that hasn't answered. Whether Claude Code is signed in is asked of the running service over its socket (a new, read-only `health` request), because a shell over ssh can't read a Mac's login keychain; before, doctor told people who were signed in to sign in again. A service that launchd or systemd doesn't have at all is said to be not loaded, where it used to read as offline.

`sessionpipe control status` is a page at a terminal, and exactly the JSON it always printed when piped or given `--json`. `--help` is one page of every command in groups, each with what it is for in a line that fits 80 columns; a command's own `--help` folds its usage between options.

Colour comes from one small module with no dependency: on at a terminal, off there with `--no-color`, `NO_COLOR` or `TERM=dumb`, on there with `FORCE_COLOR` whatever `NO_COLOR` says. A pipe is never coloured. Nothing is said by colour alone. Lines fold at the terminal's width under their own text, never inside a command; a pipe gets whole lines, as before. Nothing a program reads has changed: hook output, the worker, the status line, every `--json`, the daemon's log.

What changes for a script, and what does not:

- **`doctor`'s exit code.** `sessionpipe doctor` exits 1 when **To fix** holds a command to run, and 0 otherwise; it used to exit 0 always. A finding with nothing to type (a slow hook, a receiver that hasn't answered yet, a disk that was full and has room again, hooks an agent's own setting turns off) is on the page and counted in the verdict, and leaves the code at 0, so the code does not change with this computer's load. `doctor --json` exits 0 whatever it finds, as before. `status` exits 0, as before.
- **A command that fails.** Where stderr is a terminal it prints two lines: `error` with what is wrong, and `try` with the one command to run next. That command is the one the code that failed names, or the failing command's own `--help`; it is never read out of the message, which may be a receiver's or npm's words. Where stderr is not a terminal it is the one line it always was, `sessionpipe: <message>`, and exit 1.
- **`control pair` when a program runs it.** Not at a terminal its lines are the ones it has always written, to the byte: the link, `The page shows these digits too: 123456` or `enter:  123 456`, `✓ Paired with …`, `Daemon: …`. At a terminal the link and the digits stand each on a line of their own (`open:`, `check:` or `enter:`), and the last line starts `Background service:`.
- **Lines that are worded anew, at a terminal and in a pipe.** `doctor`, `status` and `--help` are new pages, and `control mode` sets each mode out on its own line. `install` says `This computer: <name>` where it said `Machine: <name>`, `No coding agent found on this computer` where it said `No supported harness found on this machine`, and `Nothing leaves this computer yet` where it said `this machine`. `ask on`, `ask off` and `pool on` say `Background service: …` where they said `Daemon: …`. `Renamed the background service`, `The background service uses the new list within seconds` and `The background service uses the new setting within seconds` said `the control daemon`. `sink list` and `pool` keep their old lines in a pipe and get a layout that fits at a terminal. The line `ask <agent>` writes to stderr when the service goes away is unchanged.
- **`--no-color`** is taken out of the arguments wherever it stands, before the command reads them, so it is never the value of the option before it.
- **`doctor --json`.** The shape is the same. `claude_accounts[].signed_in` is now what the running background service sees, where it can be asked, and this shell's view only where it can't. `warnings` keeps its old strings and may hold three new ones: `the background service isn't loaded: <launchd|systemd> doesn't have it`, `this computer's disk is full: <n> MB left` (or `this computer's disk was full <when> ago, by the background service's log`), and `the pool has no account with room left: Claude Code sessions here are being refused`. `update.off` keeps the words it had.
- **Words that are not sessionpipe's own** (a receiver's reason or last error, npm's last lines, a name from a file) are shown as words: escape sequences, other control characters and the characters that turn the writing direction round are taken out of every line written for a person, and a line break inside such a value is a space.
- **Commands printed for pasting** (under **To fix**, and after `try`) quote a path, a name or an address a shell would otherwise act on.

`sessionpipe-core/service` gains `serviceState`: whether launchd or systemd has a service now, without changing anything.

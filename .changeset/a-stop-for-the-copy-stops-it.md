A Stop addressed to a session's copy stops the turn the daemon is running in it. The daemon looked its run up only under the id of the session the message had named, so a Stop sent from the copy's own page (where the fork's ack and the copy's events send a person) was refused with "a Claude Code process this computer's daemon didn't start is running that session (pid …)", naming the daemon's own child. A run is now found under the session's id, the id of the copy it runs in, and the id of a copy it is still making once that has named itself.

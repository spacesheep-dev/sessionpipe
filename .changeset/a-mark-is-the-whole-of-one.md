Two things about the mark a message delivered in place is recognised by. A reply is no longer ended by the message's own mark: Claude Code records a Stop block in several rows, and had it written the attachment before the feedback row, the feedback row would have read as the next Stop block and the reply would have come back empty. And a mark is only one when it is whole (`message` and the last twelve characters of a ULID, or a channel tag's `message_id` with all twenty-six): the id it is made from is the receiver's and unsigned, and one such as "42" made the mark "message 42", which a prompt anybody typed could carry, so that turn's answer could have been sent back as the reply. A message whose id is not a ULID is still delivered; its ack carries no reply.
